# Файлы прошивок

Этот каталог содержит образы, на которые ссылается
`app/config/device-catalog.json`. Конфигурация образов формируется автоматически
скриптом `scripts/sync-firmware-config.ps1`.

## Текущее содержимое

В рабочем комплекте находятся реальные прошивки БОЦ-В-6 и БОЦ-В-12:

```text
flash/
├── boc-v12/
│   └── BOCv12_ADCVibr_Digital20260818_1450.hex
├── boc-v6/
│   ├── BOCv6_ADCVibr_Digital20260721_1111.hex
│   └── BOCv6_ADCVibr_Digital20260826_1458.hex
└── README.md
```

Для каждой модели с доступными образами используется отдельная подпапка.
Тестовые образы и файлы-заглушки в рабочий комплект не включаются.

В имени файла рекомендуется указывать модель, назначение и версию. Заменить файл
с тем же именем можно, но после этого обязательно запустите синхронизацию: она
обновит SHA-256. Для удобства анализа журнала новой версии лучше дать новое имя.

## Поддерживаемые данные

Текущая конфигурация использует:

- `.bin` — бинарный образ;
- `.hex` — Intel HEX, в артефакте указывается `"format": "intelHex"`;
- `target: "application"` — основное приложение;
- `target: "bootloader"` — загрузчик;
- `target: "plis"` — образ ПЛИС, если он поддерживается устройством и workflow.

Поддержка формата зависит не только от расширения, но и от стратегии прошивки и
параметров конкретного устройства. Не добавляйте новый формат без реализации его
чтения в коде.

Intel HEX обрабатывается как разреженная карта: приложение записывает и проверяет
только страницы, в которых файл содержит данные. Пропуски между адресными
диапазонами не заполняются и не стираются.

## Как добавить или заменить прошивку

### 1. Скопировать файл

Поместите образ в подпапку соответствующей модели, например:

```text
app/flash/boc-v6/BOCv6_Application_20260901_1200.hex
```

### 2. Обновить конфигурацию

Из корня проекта:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\sync-firmware-config.ps1
```

Скрипт:

- находит `.hex` и `.bin` в подпапках моделей;
- проверяет структуру и контрольные суммы Intel HEX;
- извлекает из образа дату и время компиляции (`Jul 21 2026` и `11:59:00`);
- создаёт идентификатор, версию и регулярное выражение распознавания;
- рассчитывает SHA-256;
- добавляет новые версии, обновляет заменённые и удаляет записи отсутствующих файлов;
- назначает самой новой версии признак `default` и создаёт разрешённые переходы.

Если необходимо только проверить актуальность каталога без его изменения:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\sync-firmware-config.ps1 -Check
```

При одинаковой версии внутри двух файлов, повреждённом HEX, неизвестной подпапке
или отсутствии даты компиляции скрипт завершится с ошибкой и не изменит каталог.
SHA-256 защищает от выбора повреждённого или случайно заменённого файла.

### 3. Как формируется запись

Параметры памяти (`target`, `addressBase`, `flashNum`, `pageSize`, `pagesCount`),
workflow и стратегия копируются из существующей шаблонной записи данной модели.
Например, результат для БОЦ-В-6 выглядит так:

```json
{
  "id": "sw-2026-09-01-12-00-00",
  "title": "БОЦ-В-6 Application",
  "version": "2026-09-01 12:00:00",
  "descriptionRegex": "\\(SW Sep 01 2026 12:00:00\\)$",
  "artifact": {
    "target": "application",
    "relativePath": "flash/boc-v6/BOCv6_Application_20260901_1200.hex",
    "sha256": "РАССЧИТАННЫЙ_SHA256",
    "format": "intelHex",
    "addressBase": "0x08040000",
    "default": true,
    "flashNum": 1
  },
  "installation": {
    "workflow": "firmware.application.standard",
    "strategy": "page-flash"
  }
}
```

Для совершенно новой модели сначала один раз вручную добавьте устройство,
`firmwareCatalogs` и одну проверенную шаблонную прошивку. После этого следующие
файлы этой модели сможет обслуживать скрипт. Не копируйте параметры памяти от
другой модели без проверки протокола и карты памяти.

### 4. Переходы между версиями

Скрипт сохраняет существующие правила переходов и автоматически добавляет
разрешённые прямые и обратные переходы для новых версий. Записи, относящиеся к
удалённым файлам, также удаляются.

```json
{
  "from": "sw-2026-08-26-14-55-55",
  "to": "sw-2026-09-01-12-00-00",
  "enabled": true
}
```

Если устройство известно, но его текущая версия не распознана, приложение показывает
все прошивки этой модели.

### 5. Проверить и собрать

Проверьте JSON и пересоберите нужную редакцию:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\sync-firmware-config.ps1 -Check
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\build-releases.ps1 -Edition internal
```

Сборка сначала сама запускает синхронизацию конфигурации, затем формирует
`app/embedded_resources.qrc` и компилирует весь набор прошивок внутрь `.exe`.
Каталог `releases/<edition>/flash` не создаётся; заменить прошивку в готовом релизе
без пересборки приложения нельзя.

## Проверка перед использованием

Перед массовой прошивкой:

1. Убедитесь, что SHA-256 в JSON совпадает с файлом.
2. Проверьте `target`, `flashNum`, базовый адрес и стратегию.
3. Выполните прошивку одного устройства.
4. Убедитесь, что verify прошёл и основное приложение загрузилось.
5. Выполните повторный поиск и проверьте определившуюся версию.
6. Только после этого запускайте групповую операцию.

В рабочий каталог добавляются только проверенные производственные образы. Для них
должна использоваться подходящая реальная стратегия, например `page-flash`.
